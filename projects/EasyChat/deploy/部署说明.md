# 部署说明

返回项目主页：[[../README]] ｜ 查看 [[../architecture/架构说明]]

## 环境要求

- JDK 21（与 Maven 3.9+）
- Node.js `^22.18.0 || >=24.12.0` 与 npm（前端 Web 与 Electron 构建）
- Docker 与 Docker Compose（用于运行容器化中间件或整套应用栈）

## 部署步骤

### 方式一：全栈 Docker Compose（本机一键启动中间件 + 微服务）

1. 进入 `D:\workspace\EasyChat\deploy`，复制 `.env.example` 为 `.env` 并按需修改变量（**勿提交 `.env` 至 Git**）。
2. 执行 `docker compose up -d --build`：
   - 先拉起基础容器：MySQL 8.4（`:3306`，挂载 `mysql/init/01-databases.sql` 自动创建 `easychat_user` 与 `easychat_chat`）、Redis 7.4（`:6379`）、Nacos v2.4.3（`:8848` / `:9848`）、Kafka 3.9.0（`:9092`）。
   - 再使用多阶段 `backend/Dockerfile` 编译启动 `easychat-user`（`:8081`）、`easychat-chat`（`:8082` / `:8083`，开启 `WS_DELIVERY=kafka`）与 `easychat-gateway`（`:8080`）。

### 方式二：独立中间件 + 仅容器化应用服务

- 当 MySQL / Redis / Nacos 已在独立服务器或宿主机运行时，使用 `deploy/docker-compose.apps.yml`（可配合 `deploy/docker-compose.kafka.yml` 启动单节点 Redpanda v24.2.4 作为 Kafka Broker），环境变量按 `deploy/.env.server.example` 准备本地 `.env`。

### 方式三：Windows 本地多进程与前端 / 桌面端构建

1. 确保 Nacos(`8848`)、MySQL(`3306`)、Redis(`6379`)、Kafka(`9092`) 已就绪（如使用 local 模式可不启 Kafka）。
2. 在 `D:\workspace\EasyChat\backend` 运行 `build.bat` / `mvn package`，或直接运行 `start-all.bat` 按序拉起三服务（关闭用 `stop-all.bat`）。
3. 进入 `D:\workspace\EasyChat\frontend\easychat`：
   - 开发调试 Web：`npm install && npm run dev`（Vite 代理 `/api` 与 `/ws` 至 `http://localhost:8080`）。
   - 开发调试桌面端：`npm run electron:dev`（加载 `.env.electron`）。
   - 打包 Windows/macOS/Linux 安装包：`npm run electron:build`（或 `--dir` 免打包预览 `npm run electron:pack`）。

## 配置项说明

> [!CAUTION] 安全约定
> 严禁在文档或公开仓库写入密码、密钥、token、云账号秘钥或真实生产主机连接串明文。以下仅记录变量名与存放位置。

| 环境变量 / 配置项 | 含义 | 存放位置 / 获取方式 |
|---|---|---|
| `SPRING_PROFILES_ACTIVE` | 激活配置档（`local` 或 `docker`） | 各模块 `application.yml` 默认 `local`；Docker Compose 中固定为 `docker` |
| `DB_URL` / `DB_USERNAME` / `DB_PASSWORD` | `easychat_user` 与 `easychat_chat` MySQL 连接信息 | 通过 `.env` 或本地 `application-local.yml`（已被 `.gitignore` 忽略）注入 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_PASSWORD` | Redis 主机、端口与密码 | 通过环境变量或本地 `application-local.yml` 注入 |
| `NACOS_SERVER_ADDR` / `NACOS_USERNAME` / `NACOS_PASSWORD` | Nacos 注册中心与 Sentinel 规则数据源地址及凭据 | 通过 `.env` 与各模块 `application.yml` 注入 |
| `SENTINEL_DASHBOARD` | Sentinel 控制台地址（默认 `localhost:8858`） | `application.yml` 中 `spring.cloud.sentinel.transport.dashboard` |
| `JWT_SECRET` | HMAC-SHA 签名密钥（须至少 32 字符强随机密钥） | 通过 `.env` / 部署机密钥管理注入；开发环境参考 `deploy/.env.example` |
| `WS_DELIVERY` / `KAFKA_BOOTSTRAP_SERVERS` / `KAFKA_ADVERTISED_HOST` | WS 投递方式（`local`/`kafka`）与 Kafka 地址配置 | `easychat-chat` 环境变量及 `deploy/docker-compose*.yml` |
| `DUBBO_HOST` / `DUBBO_PORT` | Dubbo 注册网卡 IP 与服务端口（`20880`/`20881`） | 本地多网卡可在 `application-local.yml` 固定 IP；Docker 环境在 `application-docker.yml` 设为 `0.0.0.0` |
| `MAIL_USERNAME` / `MAIL_PASSWORD` | QQ SMTP 发信账号与授权码（端口 `465` SSL） | 通过部署 `.env` 或本地未入库配置注入 |
| `TENCENT_COS_SECRET_ID` / `KEY` / `REGION` / `BUCKET` / `URL_PREFIX` | 腾讯云对象存储 COS 上传凭据与域名 | 通过部署 `.env` 或本地未入库配置注入 |

## 常见问题

- **网关把 HTTP 请求错转到 Dubbo 端口（`20880`/`20881`）**：源码中已将 `dubbo.application.register-mode` 设为 `interface` 并启用 `FORCE_INTERFACE`，避免应用级注册与 Nacos HTTP 实例端口冲突，变更配置时需保持该设置。
- **本机多网卡环境 Dubbo RPC 调用超时**：`application.yml` 注释提示 `127.0.0.1` 可能被 Dubbo 替换为其他网卡地址，可在不入库的 `application-local.yml` 中显式固定 `DUBBO_HOST`。
- **Kafka 容器客户端连不上**：启动 `docker-compose.kafka.yml`（Redpanda）或 `docker-compose.yml` 时需设置宿主机/服务器可达的 `KAFKA_ADVERTISED_HOST`。
- **Electron 下路由刷新白屏或窗口比例异常**：Electron 模式下 `router/index.ts` 与 `electron/windowMode.ts` 使用 Hash 路由监听（`#/login` 为 400×720，其余为主窗 1280×840），保持 `vite --mode electron` 编译即可。
