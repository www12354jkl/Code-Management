## 踩坑记录
- **问题**：新建空库执行 Flyway 迁移时 `V4__message_recall.sql` 会因 `status` 列重复而失败，且 `V1__baseline.sql` 中单聊相关 `conversation_id` 只有 `VARCHAR(36)` 无法写入 `uidA_uidB`。
- **原因**：基线脚本已包含 `status` 列且历史手改库曾在线上放宽字段长度，导致基线脚本与增量脚本语义不一致。
- **解决**：将 `V4` 改为 `INFORMATION_SCHEMA` 条件变更，并新增 `V7__widen_conversation_id.sql` 安全扩容至 `VARCHAR(73)`（已有历史库若已登记旧版 `V4` 校验和，需先执行一次 `flyway:repair`）。

- **问题**：前端 `npm run type-check` 失败，且 `logout.test.mjs` 在仓库根目录执行时偶发 `getActivePinia()` 报错。
- **原因**：`tsconfig.node.json` 将运行在渲染预加载环境的 `electron/preload.ts` 划入纯 Node 类型检查；测试脚本在 Windows 盘符大小写不一致时触发 Node ESM 与 Vite SSR 加载两份 `pinia` 实例。
- **解决**：为 `preload.ts` 独立配置含 `DOM` lib 的 `tsconfig.preload.json`，测试中用 `fsSync.realpathSync.native` 规范化 `rootDir` 并统一经 Vite SSR 加载 `vue`/`pinia`/`vue-router`。

- **问题**：`WsSessionManagerTest` 并发重连压测偶发 `UnnecessaryStubbingException`。
- **原因**：`register` 连续 40 轮都在 `unregister` 前拿到分段锁时 `markOffline` 从未被调用，触发 Mockito 默认严格存根校验。
- **解决**：将 `markOffline` 桩改为 `lenient().doAnswer(...)`，并补全“先下线后重连”与“先重连后旧连接断开”的确定性用例。
