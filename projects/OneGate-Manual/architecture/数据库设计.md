# 数据库设计

关联文档：[[../README|项目 README]] ｜ [[架构说明]] ｜ [[Redis与RabbitMQ设计]] ｜ [[html/onegate-erd.html|OneGate 数据库 E-R 图]]

## 一、库级约定与 E-R 图

- 交互式 E-R 图：[[html/onegate-erd.html|OneGate 数据库 E-R 图]]
- 数据库名：`onegate`（MySQL `8.0.36`，引擎 `InnoDB`，字符集 `utf8mb4` / `utf8mb4_unicode_ci`）
- 关联模式：初始化脚本 `init.sql` 关闭了物理外键检查（`SET FOREIGN_KEY_CHECKS = 0`），表之间通过 `tenant_id`、`channel_code` 进行应用层逻辑关联。
- ORM 映射：MyBatis-Plus `3.5.9`，开启 `map-underscore-to-camel-case: true`，主键策略 `id-type: auto`。

## 二、核心表结构

### 1. 租户账户表 `ai_tenant_account`

记录租户全局配额状态、压测黄金对账基准与 RPM 限流阈值（对应实体 `TenantAccount`）。

| 字段 | 类型 | 约束 / 默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, `AUTO_INCREMENT` | 主键 ID |
| `tenant_id` | `VARCHAR(64)` | `NOT NULL`, `UNIQUE uk_tenant_id` | 租户唯一标识（如 `tenant_001`） |
| `api_key` | `VARCHAR(128)` | `NOT NULL`, `UNIQUE uk_api_key` | 租户访问密钥 |
| `init_quota` | `BIGINT` | `NOT NULL DEFAULT 0` | 初始总配额（Token 数，压测黄金对账基准） |
| `avail_quota` | `BIGINT` | `NOT NULL DEFAULT 0` | 当前可用配额（Token 数） |
| `frozen_quota` | `BIGINT` | `NOT NULL DEFAULT 0` | 当前冻结配额（Token 数） |
| `used_quota` | `BIGINT` | `NOT NULL DEFAULT 0` | 累计已结算实耗配额（Token 数） |
| `rpm_limit` | `INT` | `NOT NULL DEFAULT 60` | 每分钟最大请求数限制 |
| `status` | `TINYINT` | `NOT NULL DEFAULT 1` | 状态：`1`-正常，`0`-欠费封禁 |
| `created_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE` | 更新时间 |

### 2. Token 唯一流水表 `ai_token_ledger`

基于 `uk_req_id` 唯一索引实现高并发与死信重试下的严格幂等持久化（对应实体 `TokenLedger`）。

| 字段 | 类型 | 约束 / 默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, `AUTO_INCREMENT` | 主键 ID |
| `req_id` | `VARCHAR(64)` | `NOT NULL`, `UNIQUE uk_req_id` | 全局唯一请求 ID（幂等防重） |
| `tenant_id` | `VARCHAR(64)` | `NOT NULL`, `KEY idx_tenant_created` | 所属租户 ID（逻辑关联 `ai_tenant_account.tenant_id`） |
| `model_name` | `VARCHAR(64)` | `NOT NULL` | 请求模型名称（如 `deepseek-chat`） |
| `channel_code` | `VARCHAR(64)` | `DEFAULT NULL` | 实际命中渠道编码（逻辑关联 `ai_model_channel.channel_code`） |
| `frozen_tokens` | `INT` | `NOT NULL DEFAULT 0` | 预冻结 Token 数 $(F)$ |
| `actual_tokens` | `INT` | `NOT NULL DEFAULT 0` | 实际消耗 Token 数 $(A)$ |
| `refund_tokens` | `INT` | `NOT NULL DEFAULT 0` | 多退差额 Token 数 $(F - A)$ |
| `status` | `VARCHAR(32)` | `NOT NULL` | 流水状态：`FROZEN` / `SETTLED` / `ROLLED_BACK` |
| `created_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP`, `KEY idx_tenant_created` | 创建时间 |
| `updated_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE` | 更新时间 |

索引设计：`PRIMARY KEY (id)`、`UNIQUE KEY uk_req_id (req_id)`、`KEY idx_tenant_created (tenant_id, created_at)`。

### 3. 大模型渠道表 `ai_model_channel`

支撑同一模型的多渠道平滑加权负载均衡、故障隔离与上游端点配置（对应实体 `ModelChannel`）。

| 字段 | 类型 | 约束 / 默认值 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | PK, `AUTO_INCREMENT` | 主键 ID |
| `channel_code` | `VARCHAR(64)` | `NOT NULL`, `UNIQUE uk_channel_code` | 渠道编码（如 `deepseek_ch1`） |
| `model_name` | `VARCHAR(64)` | `NOT NULL` | 支持的模型名称 |
| `base_url` | `VARCHAR(255)` | `NOT NULL` | 上游接口地址 |
| `masked_key` | `VARCHAR(255)` | `NOT NULL` | 上游调用密钥（仅存于库表，不在文档留存明文） |
| `weight` | `INT` | `NOT NULL DEFAULT 10` | 负载均衡权重 |
| `status` | `TINYINT` | `NOT NULL DEFAULT 1` | 状态：`1`-启用，`0`-隔离 |
| `created_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `DATETIME` | `NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE` | 更新时间 |

## 三、持久层核心 SQL 与对账逻辑

1. **结算配额扣减**（`TenantAccountMapper.deductSettledQuota`）：
   - 按 `tenant_id` 原子执行 `used_quota = used_quota + actual`、`avail_quota = avail_quota - actual`，由 `QuotaSettleConsumer` 在流水首次跃迁为 `SETTLED` 时调用。
2. **黄金对账汇总**（`TokenLedgerMapper.sumSettledActualTokens` & `AdminController.reconcile`）：
   - 统计指定租户 `status = 'SETTLED'` 流水的 `COALESCE(SUM(actual_tokens), 0)`，并在 `/admin/reconcile/{tenantId}` 核对等式：
     `init_quota == redisAvail + redisFrozen + settledActualTokens`
3. **当前实现状态**：
   - `QuotaBillingRpcServiceImpl` 通过 MyBatis-Plus 读写 `ai_tenant_account` 与 `ai_model_channel`。
   - `QuotaSettleConsumer` 与 `QuotaTimeoutRollbackConsumer` 已实现 `ai_token_ledger`（基于 `uk_req_id` 幂等插入/状态推进）及 `ai_tenant_account` 配额落库。
   - `AdminController` 已提供对账、租户配额一键重置（`/admin/tenant/reset-quota`）、流水查询（`/admin/ledger/list`）及渠道权重启停（`/admin/channel/weight`）接口。
