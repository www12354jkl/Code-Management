## 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| `onegate-common`（已完成） | 定义 Dubbo RPC 契约 `QuotaBillingRpcService`、Redis/RabbitMQ 常量、流水状态枚举 `QuotaLedgerState` 及 9 个传输 DTO | Lombok、Fastjson2、Jakarta Validation |

## 关键数据流

1. **鉴权、本地短路与配额预冻结（已全链路贯通）**
   - 请求进入 `ChatCompletionController.chatCompletions`（`POST /v1/chat/completions`），先校验 `Authorization` Bearer API Key 并通过 60 秒 Caffeine `tenantAuthCache` / Dubbo `getTenantByApiKey` 获取租户信息（支持开发兜底测试租户，具体测试凭据见源代码与 `init.sql`）。
   - 校验 Caffeine `shortCircuitCache`（5 秒 TTL 欠费短路黑名单），命中则在 `< 0.1ms` 直接返回 `402`，避免穿透至 Redis。
   - 构造 `PreFreezeRequest`（默认预冻结 `500` Token，支持传入 `max_tokens` 并限制在 `[50, 2000]`），调用 `QuotaBillingRpcService.preFreezeQuota`（不足 `-2` 时写入 5s 欠费短路缓存返回 `402`，RPM 超限 `-1` 返回 `429`，幂等拦截 `0` 返回 `409`）。
   - `QuotaBillingRpcServiceImpl` 先按租户预热 Redis 可用/冻结配额（`ensureTenantQuotaWarmUp`），随后执行 `pre_freeze.lua`：
     - 检查 `onegate:req:{req_id}` 幂等拦截（返回 `0`）；
     - 检查 `onegate:rate:rpm:{tenant_id}:{epoch_min}` 分钟级 RPM（超限返回 `-1`）；
     - 检查 `onegate:quota:avail:{tenant_id}` 可用额度（不足返回 `-2`）；
     - 原子扣减可用额度、累加冻结额度，写入 `FROZEN` 状态 Hash（24 小时过期，返回 `1`）。
   - 预冻结成功后向 `onegate.billing.exchange` 投递 `TimeoutCheckMessage` 至 5 分钟 TTL 延迟队列 `onegate.billing.timeout.delay.queue`。

2. **多渠道路由熔断与正常结算（已全链路贯通）**
   - `ChannelRouter.forwardWithFailover` 拉取活跃渠道并用 `SlidingWindowCircuitBreaker`（10 秒环形桶滑动窗口；样本 `>= 5` 且错误率 `>= 50%` 触发 `OPEN`，冷却 `5000ms` 后 CAS 转入 `HALF_OPEN` 试探）过滤健康渠道；遇到 HTTP `429` / `5xx` 或异常时自动 Failover 至备用渠道，对 `/mock/llm/` 本地仿真端点支持进程内低延迟直通。
   - 上游返回成功后，`ChatCompletionController.sendAsyncSettleMessage` 解析 `usage.total_tokens` 实际消耗并通过 RabbitMQ 发送 `SettleMessage` 至 `onegate.billing.settle.queue`。
   - `QuotaSettleConsumer` 监听结算队列，调用 `settleQuota`（执行 `settle_quota.lua`）校验 `FROZEN` 状态后计算 `refundTokens = frozenTokens - actualTokens` 实现多退少补，释放冻结额度并将状态推进为 `SETTLED`；随后在同一事务内基于 `uk_req_id` 插入/更新 `ai_token_ledger` 并调用 `TenantAccountMapper.deductSettledQuota` 扣减账户可用额度、累加已耗额度（含 Redis 已结算但 DB 异常后的重试补偿逻辑）。

3. **异常即时回滚与超时死信兜底（已全链路贯通）**
   - 当所有候选渠道均失败或处于熔断隔离状态时，`ChatCompletionController.sendImmediateRollback` 立即向 `onegate.billing.timeout.rollback` 路由键投递回滚消息并向客户端返回 `503`。
   - 若网关进程宕机或请求长期悬挂未结算，`onegate.billing.timeout.delay.queue` 消息 5 分钟 TTL 到期后自动转发至死信交换机 `onegate.billing.dlx.exchange`，进入 `onegate.billing.timeout.rollback.queue`（同时支持 `/admin/test/freeze-only` 2 秒测试队列演练）。
   - `QuotaTimeoutRollbackConsumer` 消费后调用 `rollbackQuota`（执行 `rollback_quota.lua`），仅对 `FROZEN` 状态的请求执行全额退回并流转为 `ROLLED_BACK`，随后将结果落库 `ai_token_ledger`。

## 在线监控与混沌实验台（`static/index.html`）

网关启动后访问 `http://127.0.0.1:8080/` 可进入实时控制台（每 1.5s 轮询 `:8080` 与 `:8081`）：
- **实时配额天平 · 黄金对账**：展示 `Init`、`Avail`、`Frozen`、`Used` 四项守恒指标与 `误差 0 Token` 对账横幅，并提供「重置 10,000 额度」「并发争抢额度」「注入悬挂死账」三项混沌实验按钮。
- **渠道熔断与 Failover 沙盘**：展示各渠道 `CLOSED / OPEN / HALF_OPEN` 状态、滑动窗口错误率及 `429` 故障注入开关（联动 `/v1/gateway/channels/health` 与 `/mock/llm/{channelCode}/fault`）。
- **OpenAI 兼容接口调试台与流水表**：支持直接发起 `POST /v1/chat/completions` 请求并实时观测最近 10 条 `SETTLED` / `ROLLED_BACK` 流水。

## 外部依赖与服务

- **MySQL 8.0.36**（库名 `onegate`）：包含 `ai_tenant_account`（租户账户与配额基准）、`ai_token_ledger`（`uk_req_id` 唯一幂等流水）、`ai_model_channel`（上游模型渠道与权重），详见 [[数据库设计]] 与 [[html/onegate-erd.html|数据库 E-R 图]]。
- **Redis 7.2**：承载租户可用/冻结余额、请求状态机凭证 Hash、分钟级 RPM 计数及 3 个原子 Lua 脚本执行，详见 [[Redis与RabbitMQ设计]]。
- **RabbitMQ 3.13**：承担异步结算队列、5 分钟 TTL 延迟队列、DLX 死信交换机、死信回滚队列及 2 秒测试延迟队列，详见 [[Redis与RabbitMQ设计]] 与 [[../flows/redis-rabbitmq-billing-flow.html|计费与死信回滚流程图]]。
- **Nacos 2.3.2**：作为 Apache Dubbo 的服务注册与发现中心（`public` 命名空间）。
